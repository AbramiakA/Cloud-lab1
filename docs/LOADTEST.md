# Навантажувальне тестування REST API

## Сценарій і параметри

Для тестування REST API використано k6. Запити надсилалися до Flask-застосунку, розгорнутого в AWS ECS Fargate.

У сценарії `loadtest/products.js` одна ітерація містить 1 POST-запит для створення товару та 9 GET-запитів: читання сторінки каталогу (`page=1&limit=20`) і 8 окремих товарів, зокрема щойно створеного. Між ітераціями встановлено паузу 1 с.

Тест складається з трьох фаз:
- 3 хв — збільшення навантаження до 100 VU;
- 5 хв — стале навантаження при 100 VU;
- 2 хв — зменшення до 0 VU.

Загальна тривалість — 10 хвилин. Значення 100 VU вибрано для перевірки автоматичного масштабування під час сталої фази.

**Команда запуску:**

```powershell
$url = terraform -chdir=deploy/aws/terraform output -raw service_url
k6 run -e "BASE_URL=$url" -e TARGET_VUS=100 .\loadtest\products.js
```

## Проблема та виправлення

Під час першого тесту було 42,46% помилок. У CloudWatch Logs виявлено `Failed getting connection; pool exhausted` — не вистачало підключень до MySQL. Додаткове навантаження створювали окремі запити до бази для атрибутів кожного товару (N+1).

В образі `1.1` прибрано читання всього каталогу зі сценарію та додано повторні спроби підключення.

В образі `1.2` використано `SQLAlchemy QueuePool` (5 основних і до 5 додаткових підключень, очікування до 10 с), виправлено закриття з'єднань у DAO, додано пагінацію та пакетне читання атрибутів.
